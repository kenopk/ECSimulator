# PROJECT_MAP — GOVNO (симулятор электрических цепей, C++ / Qt)

> Состояние на 15.10.2026: **gui переписан заново (v0.2), ядро (core) ещё не написано.**

## 1. Что это за проект

Десктопный клон https://www.falstad.com/circuit/circuitjs.html: схема рисуется на бесконечном поле,
потом цепь считается и показывается в реальном времени. Дизайн — «как Falstad, но современнее»:
тёмная минималистичная тема, условные обозначения по ГОСТ 2.721-74 (и смежным ГОСТ ЕСКД).

**Главное требование автора:** проект из 2 независимых частей, которые обновляются по отдельности.

| Часть | Что делает | Зависимости |
|---|---|---|
| **core** (ядро) | Реестр элементов, модель цепи, расчёт (MNA), сохранение/загрузка. Без GUI. | Только C++17 (максимум `QtCore`) |
| **gui** (оболочка) | Окна, холст, рисование символов, ввод, диалоги, темы. | Qt Widgets + заголовки ядра |

## 2. Технологии

- C++17, Qt 6 (у автора Qt 6.11, MinGW 64-bit), CMake ≥ 3.16, `AUTOMOC`, `AUTORCC`
- IDE: Qt Creator, Windows. Папка проекта: `F:\project\qt\GOVNO`. Цель сборки: `GOVNO` (модуль Qt: `Widgets`)
- Язык комментариев и интерфейса: русский

## 4. Реестр элементов (общий контракт core ↔ gui)

Файл `core/include/govno/core/ElementTypes.h` — **единственный источник правды** об элементах.
GUI строит из него меню, иконки, форму параметров и диалог свойств; ядро будет брать из него
имена выводов и параметры для расчёта.

`ElementInfo { type, id, name, category, pinNames, params }`
`ParamDef { key, label, unit, defaultValue, minValue, maxValue, choices }` — значения в СИ;
если `choices = "А|Б|В"`, параметр — перечисление (значение = индекс).

**Порядок `pinNames` — контракт gui ↔ core:** вывод `i` в GUI = вывод `i` в ядре.

Реализовано **180 типов** (в Falstad их ~150, плюс радиоэлементы). Категории в меню (ПКМ → «Все элементы»):

| Категория | Элементы |
|---|---|
| Провода, земля, метки | провод, земля, корпус, метка узла (одноимённые соединены) |
| Пассивные | резистор, переменный резистор, потенциометр, конденсатор (обычный, полярный, переменный), катушка (обычная, дроссель, переменная), трансформатор, трансформатор со средней точкой, автотрансформатор, связанные катушки, предохранитель, лампа, мемристор, фоторезистор, терморезистор (NTC/PTC), варистор, разрядник |

**Микросхемы** описываются одной строкой в реестре (`ElementInfo::chip`), корпус рисуется автоматически
(`SymbolPainter`, `chipGeom/paintChip`):

```
chipInfo(T::DFlipFlop, "dff", "D-триггер", C::Digital, "D;D,>C|Q,/Q", { ...параметры... })
                                                         │  │ │ │  └ правые выводы
                                                         │  │ │ └ '/' — инверсия (кружок и надчёркивание)
                                                         │  │ └ '>' — вход синхронизации (треугольник)
                                                         │  └ левые выводы (сверху вниз), '|' — граница
                                                         └ заголовок; "@relay/@opto/@seg7/@ledm/@dmat" — особый рисунок
```
Имена выводов, их число и высота корпуса берутся из этой строки; ширина — по длине подписей.
Шаг выводов — 2 клетки (как у вентилей), длину по оси можно растягивать.

### Как добавить новый элемент (3 шага)
1. `ElementTypes.h`: добавить значение в `enum class ElementType` (до `Count_`) и **одну запись в `allElements()` в том же порядке**.
   Для микросхемы — запись через `chipInfo(...)` со строкой-раскладкой, **шаг 2 не нужен**: корпус нарисуется сам.
2. Обычный (не микросхема) элемент: `gui/items/SymbolPainter.cpp` — строка в `spec()` (выводы, размеры) и функция рисования
   (новые функции — в `SymbolPainterExtra.inc`). Выводы посередине оси (u = 0.5) требуют `stepGrid = 2`, чтобы попадать в сетку.
3. (по желанию) горячая клавиша — таблица `kKeys` в `gui/app/EditorWindow.cpp`.
Меню, иконка, диалог свойств и панель параметров появятся сами.

## 5. Архитектура gui

```
MainWindow ── QStackedWidget ── стартовая страница
                             └─ EditorWindow
                                 ├─ EditorTabs (QTabWidget, вкладка = схема)
                                 │    └─ CircuitView ── CircuitScene ── CircuitItem × N
                                 │         └─ QUndoStack (свой на вкладку; QUndoGroup в EditorWindow)
                                 ├─ левая панель инструментов (верхней панели нет — всё есть в меню и по ПКМ)
                                 └─ правая панель: SimulationPanel + PropertiesPanel
```

- **CircuitItem** — один класс на провод и все элементы. Геометрия: концы `p1`/`p2` на сетке 16 px + `flip`.
  Выводы берутся из `SymbolPainter::spec()` (доля длины вдоль оси + смещение поперёк в клетках).
  Для сетки ядра: `CircuitItem::connectionPoints()` отдаёт точки выводов, `setElectrical(pinV, current)` принимает результат расчёта.
- **Соединение определяется геометрически** (совпали точки выводов) в `CircuitScene::rebuild()` через union-find.
  Позже заменить на явные связи ядра (`connect(PinId, PinId)`).
- **Undo:** «уже применено вживую, redo идемпотентен» (перенос, поворот, параметры — один шаг отмены).
- **Тема:** `Theme` — синглтон, QSS собирается из токенов `@bg@ @panel@ @border@ @accent@ @onAccent@ …`. Пресеты: Полночь, Графит, Океан, Чисто чёрный, Чисто белый, «Свой цвет» (фон выбирает пользователь, остальное выводится; светлый фон → тёмные линии). Свой цвет акцента — отдельно; галочки чекбоксов рисуются в файл-PNG цветом `onAccent`.

## 6. Управление

**Перемещение (режим «Выбор»)**

| Действие | Результат |
|---|---|
| тянуть тело элемента | переносятся выделенные элементы, провода остаются на месте |
| тянуть вывод (кружок на конце) | переносится узел: вместе с ним все концы в этой точке |
| **Shift** + тянуть что угодно | элемент переносится **целиком**, даже если схвачен за вывод/край |
| **Alt** + тянуть | как Shift, но подключённые провода растягиваются следом |
| земля/корпус | тянется как любой элемент и ставится в **любом направлении** (в т.ч. наискосок); у многовыводных (транзисторы, потенциометр, трансформатор) только 0°/90° — их выводы иначе не попадут в узлы сетки |
| стрелки / Shift + стрелки | сдвиг на 1 / 5 клеток |

**Прочее**

| Клавиша | Действие |
|---|---|
| ПКМ по схеме | список ВСЕХ элементов по категориям + действия над выделенным |
| ПКМ по вкладке | новая, дублировать, переименовать, очистить, закрыть / остальные / справа / все |
| двойной клик по элементу, F2 | окно «Свойства» со всеми характеристиками |
| двойной клик по вкладке / пустому месту полосы | переименовать / новая схема; СКМ по вкладке — закрыть |
| Ctrl+R, Ctrl+Shift+R, Ctrl+F | повернуть, повернуть назад, отразить |
| Пробел или **ЛКМ-клик** по символу | переключить ключ/кнопку/переключатель (замкнуть ↔ разомкнуть) |
| S W R C E L V A I G D T O K | выбор, провод, резистор, конденсатор, электролит, катушка, источник пост./перем., источник тока, земля, диод, NPN, ОУ, выключатель |
| закрытие последней вкладки | возврат в главное меню |
| Esc | отмена операции → режим выбора → снять выделение |
| Ctrl+Z / Ctrl+Y, Ctrl+C/X/V/A, Del | правка |
| Ctrl+T / Ctrl+W | новая / закрыть вкладку; колесо — масштаб; СКМ — панорама; Ctrl+0 / Ctrl+9 — 100% / вписать |

**Красные концы:** если вывод стоит вплотную (±1 клетка) к чужому узлу или лежит на чужом проводе,
но не соединён — он подсвечивается ярко-красным. Отключается в «Настройках».

## 6а. Параметры и единицы

В окне «Свойства» и на правой панели у каждого параметра справа выпадающий список единиц
(`ParamForm`, `UnitCombo`). Смена единицы **пересчитывает число**: 1000 V → выбрал kV → в поле 1.
При вводе «4.7k», «100n» единица подбирается автоматически. Справка по суффиксам — `ParamForm::suffixHelp()`.

| Суффикс | Приставка | Множитель |
|---|---|---|
| p | пико | 10⁻¹² |
| n | нано | 10⁻⁹ |
| u / µ | микро | 10⁻⁶ |
| m | милли | 10⁻³ |
| (нет) | — | 1 |
| k | кило | 10³ |
| M | мега | 10⁶ |
| G | гига | 10⁹ |

Единицы: Ω — Ом, F — фарад, H — генри, V — вольт, A — ампер, Hz — герц, W — ватт; % и ° — без приставок.

## 7. Правая панель

- **Симуляция** (`SimulationPanel`): «Сброс», «Старт/Стоп», ползунки «Скорость симуляции» (1/32×…32×),
  «Скорость тока» (бегущие точки), «Яркость мощности». Значения запоминаются (`QSettings`).
  Панель только испускает сигналы (`runningChanged`, `simulationSpeedChanged`, `resetClicked` …);
  доступ из кода: `EditorWindow::simulationPanel()`. **Ядро подключится к этим сигналам.**
- **Элемент** (`PropertiesPanel`): быстрые поля выбранного элемента; кнопка «Все характеристики…» открывает `ElementDialog`.


### Элементы с переменным числом выводов («variant»)

Число входов вентиля, объём памяти, тип сегментного индикатора и размер матриц задаются **параметрами экземпляра**,
а не отдельными типами (старые `GateAnd3`, `RAM16x4`, `Seg7`, `LedMatrix4` и т.п. удалены).

- В реестре у `ElementInfo` есть поле `dynamic` (`Dynamic::GateInputs / Memory / DiodeMatrix / SegDisplay / LedMatrix / Bits / Keypad / Lcd / Dip`).
- `govno::core::variantOf(info, getter)` превращает параметры в число-«вариант»; `layoutFor / pinCountFor / pinNamesFor`
  по варианту строят раскладку выводов (ядро и gui берут её из одного места).
- `CircuitItem` хранит `m_variant`, пересчитывает его в `setParam/setParams` (`refreshVariant`) и передаёт в
  `SymbolPainter::*(type, …, variant)`; при смене числа выводов элемент пересчитывает геометрию и подключения.
- Параметры: вентили `inputs` (2…63); RAM/ROM `addrBits` (2 слова … 64 К слов) и `dataBits` (1…16);
  диодная матрица `inputs/outputs/preset` (≤16×16); `seg_display.segments` = 7 / 14 / 16 / 21 сегмент;
  `led_matrix.rows/cols` (1…32, по умолчанию 8×8). Целочисленные параметры помечены `ParamDef.integer`.
- **Разрядность в свойствах** (`Dynamic::Bits`, параметр `bits`): мультиплексор, демультиплексор, дешифратор, шифратор
  (адресных линий 1…5 → 2…32 канала), регистр, АЦП/ЦАП, сумматор, компаратор, приёмопередатчик, счётчик с загрузкой
  (1…16), SIPO/PISO, двоичный счётчик, разветвитель шины, шинный вход (1…32), кольцевой счётчик (2…32), таблица истинности
  (1…5 входов), аналоговый мультиплексор. Раскладка — `bitsLayoutString()` в `ElementTypes.h` (правится в `gen/apply2.py`).
  Прежние `Mux2/Mux4/Decoder24/…/Counter8` объединены в `Mux/Decoder/…/Counter`.
- **Выводы на четырёх сторонах** (как у Falstad): `ChipPin::edge` (0 слева, 1 справа, 2 сверху, 3 снизу), раскладка
  `"ЗАГ;слева|справа|сверху|снизу"`; `PinSpec{u, v, du, side}` — у выводов сверху/снизу `u = 0.5`, `du` — смещение от центра,
  длина таких элементов кратна 2 клеткам (`stepGrid = 2`). Селекторы мультиплексоров, EN дешифратора, DIR/OE
  приёмопередатчика — снизу. Шаг выводов у модулей 16 px (плотно) или 32 px (`pinSlot()` сажает выводы на сетку).
- **Модули** (`@lcd/@keypad/@dip/@ledm`) рисуются без корпуса-обёртки: `ChipGeom::module`, `paintModuleArt()`; выводы
  подведены прямо к экрану/клавишам/переключателям/светодиодам, имена — вдоль выводов (`leadName`).
  LED-матрица: строки слева, столбцы сверху; клавиатура: строки слева, столбцы сверху; DIP: A сверху, B снизу; LCD: управление
  сверху, данные снизу. `lcd.size` — тип 16×2/16×1/8×2/20×2/20×4/16×4/40×2/40×4 (`lcdSize`),
  `keypad.rows/cols` 1…32 (клавиши пронумерованы 1…N·M, `key` — номер нажатой), `dip_switch.positions` 1…32.
- **Клики по частям**: `CircuitItem::hasParts()/partAt(scene)` ← `SymbolPainter::partAt`. Клавиатура: клавиша нажата, пока
  удерживается ЛКМ (`m_heldKeypad`, параметр `key` меняется без записи в undo; потянули — это уже перенос); DIP: щелчок без
  сдвига переключает бит `mask` (`toggleDipSwitch`, одно действие отмены). Окно свойств у обоих сохранено (двойной клик/F2).
- **Меню ПКМ**: по элементу — меню действий (`EditorWindow::showContextMenu`, шапка с значком, свойства, поворот, отражение,
  вырезать/копировать/удалить; `CircuitView::contextItem()`), по пустому месту — список всех элементов.
- Содержимое RAM/ROM (редактор ячеек) пока не реализовано — только размер.
- Маска «почти-соединений» — 64-битная (`quint64`), `SymbolPainter::kMaxPins = 64`.


### Колесо мыши над элементом и элементы без свойств

- `CircuitItem::wheelKey(secondary)` / `wheelStep(key, dir)` + таблица `kWheel` (в `CircuitItem.cpp`): колесо над элементом
  меняет главный параметр (R, C, L — ряд E12; напряжения, токи, частоты — ряд 1-1.5-2-2.5-3-4-5…; движок и
  освещённость — шаг 5 %). У переменных резисторов/конденсаторов/катушек колесо двигает `position`,
  **Shift + колесо** — номинал/частоту, **Ctrl + колесо** — всегда масштаб. Правка идёт через `setItemParam`
  (склеивается в одно действие отмены). Подпись на схеме показывает текущее значение.
- `CircuitItem::hasProperties()` — false у провода и элементов, чей единственный параметр — положение
  (выключатели, кнопки, переключатели): двойной клик по ним = два переключения, окна свойств, F2 и кнопки «Все характеристики…» нет.


### Сверка с Falstad и модули

Список «Add …» из меню Falstad (`Menus.java`) перенесён целиком, кроме «Subcircuit Instance / pin» (подсхемы — позже)
и «Op Amp (+ сверху)» (это отражение обычного ОУ, Ctrl+F). Дополнительно — категория **«Модули и платы»**:
ЖК-дисплей (`@lcd`, тип `size`), матричная клавиатура (`@keypad`, `rows`×`cols`, `key` — номер нажатой клавиши), DIP-переключатель (`@dip`, `positions`, маска `mask`),


- **Оформление** (0 выводов, категория «Провода…»): `TextLabel` (текст хранится в `CircuitItem::text()`, правится в окне
  свойств/панели через `ChangeTextCommand`), `Box` (рамка по диагонали p1–p2), `Line`. Свободная геометрия — `isFreeShape()`
  в `SymbolPainter.cpp`. К схеме не относятся (`CircuitItem::isDecoration()`).
- **Трассированный провод** (`Shift+W`): `CircuitView::setPlaceMode(Wire, routed=true)` — два провода «уголком» одним движением
  (с Shift при протяжке — сначала по вертикали).
- Одновыводные «значки» (`paintSingle`, kind 14–21): звуковой вход/выход, ввод данных, внешнее напряжение, аналоговый выход,
  контрольная точка, экспорт данных, стоп-триггер.
- Состояние для рисунка: `CircuitItem::stateValue()` (клавиатура — `key`, DIP — `mask`).
- Моделирование этих элементов ядро пока не выполняет — это только редактор.

## 8. Статус

**Готово (gui):** редактор с вкладками, сетка, масштаб, панорама, 180 элементов (по ГОСТ, где он есть), провода,
перенос/поворот/отражение, выделение рамкой, copy/cut/paste, undo/redo, диалог свойств,
правая панель симуляции, красные «почти-соединения», тема и настройки (в т.ч. чисто чёрный / чисто белый / свой цвет фона и акцента), контекстные меню (схема, вкладки).

**Не готово:**
- **core:** нет модели цепи, узлов, решателя (MNA), источников/ключей в расчёте, save/load.
- Расчёт: `SimulationPanel` пока ничего не запускает; цвета проводов по напряжению и точки тока включатся, когда ядро вызовет `CircuitItem::setElectrical`.
- Открыть/Сохранить — заглушки (формат файла опишет ядро).
- Не реализовано автоматическое разрезание провода при касании концом его середины (такой конец подсвечивается красным).
- Символы, которых нет в приложенном ГОСТ 2.721-74 (стабилитрон, Шоттки, ОУ, вентили, электролит и др.), нарисованы по общепринятым российским обозначениям и могут отличаться от стандарта в деталях.
- Осциллографы, графики, элементы Falstad сверх списка (ещё ~110 типов).

## 9. Дорожная карта

1. **core:** `Circuit` (элементы, пины, узлы), `Simulator` (MNA, шаг по времени), `Serializer` (JSON).
2. Подключить `SimulationPanel` к ядру; передавать в gui `setElectrical(pinV, current)`.
3. Явные соединения вместо геометрических (`connect(PinId, PinId)`), авто-разрезание проводов.
4. Осциллограф/график, недостающие элементы.
5. Тесты ядра (CTest, без GUI).

## 10. Как работать с этим файлом

- Меняешь структуру или API — обнови разделы 3–8.
- Новый чат: приложи этот файл + нужные исходники.
- Правило: затрагивает расчёт, формат файла, параметры элементов → **core**; отрисовка, ввод, окна → **gui**.
