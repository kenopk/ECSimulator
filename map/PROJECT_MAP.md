## 1. Что это за проект

Десктопный аналог [Falstad CircuitJS](https://www.falstad.com/circuit/circuitjs.html): схема рисуется на
бесконечном поле, затем цепь считается и показывается в реальном времени (цвет проводов по напряжению,
бегущие точки тока). Дизайн — «как Falstad, но современнее»: тёмная минималистичная тема, условные
обозначения по ГОСТ 2.721-74 и смежным ГОСТ ЕСКД (2.723, 2.728, 2.730, 2.743, 2.755, 2.759).

**Главное архитектурное требование:** две независимые части, которые обновляются по отдельности.

| Часть | Что делает | Зависимости |
|---|---|---|
| **core** (ядро) | Реестр элементов, модель цепи, расчёт (MNA), сохранение/загрузка. Без GUI. | Только C++17 (максимум `QtCore`) |
| **gui** (оболочка) | Окна, холст, рисование символов, ввод, диалоги, темы. | Qt Widgets + публичные заголовки ядра |

Правило для любого запроса: затрагивает расчёт, формат файла, параметры элементов → **core**;
отрисовка, ввод, окна → **gui**.

## 4. core — реестр элементов (общий контракт core ↔ gui)

`core/include/govno/core/ElementTypes.h` — **единственный источник правды** об элементах. Заголовок без Qt.
GUI строит из него меню, иконки, форму параметров и диалог свойств; ядро будет брать оттуда выводы и параметры.

```cpp
struct ParamDef    { key, label, unit, defaultValue, minValue, maxValue, choices = nullptr, integer = false };
struct ElementInfo { type, id, name, category, pinNames, params, chip = nullptr, dynamic = Dynamic::None };
```

- Значения параметров — в СИ. `choices = "А|Б|В"` → перечисление (значение = индекс). `integer` — округлять.
- `id` — стабильный строковый идентификатор (для будущего формата файлов).
- **Порядок `pinNames` — контракт:** вывод `i` в gui = вывод `i` в ядре.
- `elementInfo(type)` — быстрый доступ по индексу + страховка от рассинхрона enum и таблицы.
- `CORE_API_VERSION` пока **нет**.

### 4.2 Микросхемы — строка-раскладка (`chipInfo`)

```
chipInfo(T::DFlipFlop, "dff", "D-триггер", C::Digital, "D;D,>C|Q,/Q", { ...параметры... })
                                                        │  │ │ │  └ правые выводы
                                                        │  │ │ └ '/' — инверсия (кружок, надчёркивание)
                                                        │  │ └ '>' — вход синхронизации (треугольник)
                                                        │  └ левые выводы (сверху вниз), '|' — граница сторон
                                                        └ заголовок; '@relay/@opto/@seg7/@ledm/@dmat/@lcd/@keypad/@dip' — особый рисунок
```

- Полная форма: `"ЗАГ;слева|справа|сверху|снизу"`; `ChipPin::edge` = 0 слева, 1 справа, 2 сверху, 3 снизу.
- Имена/число выводов и высота корпуса берутся из строки, ширина — по длине подписей. Шаг выводов — 2 клетки.

### 4.3 Элементы с переменным числом выводов (`Dynamic`)

Число выводов задаётся **параметрами экземпляра**, а не отдельными типами.

| `Dynamic` | Параметры | Диапазон |
|---|---|---|
| `GateInputs` | `inputs` | 2…63 входа у вентилей |
| `Memory` | `addrBits`, `dataBits` | RAM/ROM до 64 К слов × 16 бит |
| `DiodeMatrix` | `inputs`, `outputs`, `preset` | ≤ 16×16 |
| `SegDisplay` | `segments`, `digits` | 3 (цифра «1» и знак) / 5 / 7 / 9 (семь и две диагонали) / 14 (звезда) / 16 сегментов; разрядов 1…16 |
| `LedMatrix` | `rows`, `cols` | 1…32 (по умолчанию 8×8) |
| `Bits` | `bits` | MUX/DEMUX/дешифратор/шифратор, регистры, АЦП/ЦАП, сумматор, счётчики, шины… (`bitsLayoutString()`) |
| `Keypad` | `rows`, `cols`, `key` | 1…32; `key` — номер нажатой клавиши |
| `Lcd` | `size` | 16×2 / 16×1 / 8×2 / 20×2 / 20×4 / 16×4 / 40×2 / 40×4 (`lcdSize`) |
| `Dip` | `positions`, `mask` | 1…32; `mask` — биты положений |
| `Karnaugh` | `width`, `height`, `output`, `pins` | карта Карно как элемент: 1…16 × 1…16; выводы A… (сначала переменные по строкам, затем по столбцам) и F |

Цепочка: `variantOf(info, getter)` → число-«вариант» → `layoutFor / pinCountFor / pinNamesFor`.
Ядро и gui получают раскладку из одного места. Максимум выводов — 64 (`SymbolPainter::kMaxPins`).

### 4.4 Как добавить новый элемент

1. `ElementTypes.h`: значение в `enum class ElementType` (перед `Count_`) и **одна запись в `allElements()` в том же порядке**.
   Микросхема — через `chipInfo(...)`, шаг 2 не нужен.
2. Обычный элемент: `gui/items/SymbolPainter.cpp` — строка в `spec()` и функция рисования (новые — в `SymbolPainterExtra.inc`).
   Выводы посередине оси (u = 0.5) требуют `stepGrid = 2`.
3. (по желанию) горячая клавиша — `kKeys` в `gui/app/EditorWindow.cpp`; колесо — `kWheel` в `gui/items/CircuitItem.cpp`.

Меню, иконка, диалог свойств и панель параметров появятся сами.

| `SettingsDialog` | настройки вида | применяются сразу через `Theme` |
| осциллограммы | ПКМ по элементу → «Осциллограмма»: на схему (`CircuitView::addScope`) или в нижнюю панель (`EditorWindow::showScopeInDock`). Данные идут из `CircuitItem::setElectrical` + `CircuitItem::setSimTime`; пока ядра нет, графики пустые |
| `Theme` | синглтон оформления | `Palette`, пресеты **Лаборатория («цифровая лаборатория»: графит #121315, текстолит #1a1c1f, янтарь #ff9f0a для выбора, зелёный #00e676 для сигналов и фокуса ввода; по умолчанию), Графит, Океан, Чисто чёрный, Чисто белый, Свой цвет**; свой акцент; `GridStyle {Dots, Lines, None}`; `voltageColor(V)`; QSS из токенов `@bg@ @panel@ @accent@ @onAccent@…` |
| `Units` (namespace) | единицы | `format(value, unit)`, `parse(text, unit, &out)` |

### 5.2 Принципы

- **Соединение — геометрическое:** выводы, совпавшие в одной точке сетки, = один узел (`CircuitScene::rebuild`).
  Позже заменить на явные связи ядра (`connect(PinId, PinId)`).
- **Undo: «уже применено вживую, redo идемпотентен»** — перенос, поворот, параметры дают один шаг отмены.
- **Оформление** (`TextLabel`, `Box`, `Line`) к цепи не относится: `CircuitItem::isDecoration()`.
- **Многовыводные элементы** ставятся только под 0°/90° (`axisOnly`), одновыводные — в любом направлении.
- **Красные концы:** вывод вплотную (±1 клетка) к чужому узлу или на чужом проводе, но не соединён → ярко-красный.
  Маска — `quint64` (`setNearMiss`). Отключается в «Настройках».

`sim/speed`, `sim/current`, `sim/power`.

## 6. Управление

**Перемещение (режим «Выбор»)**

| Действие | Результат |
|---|---|
| тянуть тело элемента | переносятся выделенные элементы, провода остаются |
| тянуть вывод (кружок) | переносится узел — все концы в этой точке |
| **Shift** + тянуть | элемент переносится целиком, даже если схвачен за вывод |
| **Alt** + тянуть | как Shift, но подключённые провода растягиваются следом |
| земля | тело/вывод — перенос, кружок на конце стержня — поворот |
| стрелки / Shift + стрелки | сдвиг на 1 / 5 клеток |

**Клавиши**

| Клавиша | Действие |
|---|---|
| S | режим выбора |

**Мышь:** колесо — масштаб; СКМ — панорама; ПКМ по пустому месту — все элементы по категориям; ПКМ по элементу —

**Колесо над элементом** меняет главный параметр (R, C, L — ряд E12; напряжения/токи/частоты — 1-1.5-2-2.5-3-4-5…;

**Ctrl+колесо** — всегда масштаб.

**Модули:** клавиатура — клавиша нажата, пока держится ЛКМ (без записи в undo); DIP — щелчок без сдвига
переключает бит `mask` (одно действие отмены).

## 8. Связь gui ↔ будущее ядро (точки подключения)

| Что | Где в gui |
|---|---|
| Описание элементов, выводов, параметров | `ElementTypes.h` (уже общее) |
| Точки выводов элемента | `CircuitItem::connectionPoints()`, `pinPoint(i)` |
| Узлы схемы | `CircuitScene::rebuild()` (пока геометрически) |
| Результат расчёта → отображение | `CircuitItem::setElectrical(pinVoltages, current)`, `clearElectrical()` |
| Масштаб напряжения для цвета | `Theme::setVoltageScale(V)`, `voltageColor(V)` |
| Анимация тока | `CircuitView::setFlowAnimation(on)`, `CircuitScene::tickFlow(dt)`, `CircuitItem::setFlowSpeed` |
| Старт/стоп/скорость/сброс | сигналы `SimulationPanel` через `EditorWindow::simulationPanel()` |
| Сериализация | `CircuitView::snapshot()/loadSnapshot()` + `ItemData` — готовая основа для save/load |

Набросок API ядра (цель):

```cpp
namespace govno::core {
class Circuit {   // элементы, пины, узлы
    ElementId addElement(ElementType); void removeElement(ElementId);
    void connect(PinId, PinId); void setParam(ElementId, const std::string&, double);
};
class Simulator { // MNA, шаг по времени
    explicit Simulator(Circuit&); void setTimeStep(double); bool step();
    double nodeVoltage(NodeId) const; double elementCurrent(ElementId) const;
};
bool saveCircuit(const Circuit&, const std::string& path);   // JSON, версия формата
bool loadCircuit(Circuit&, const std::string& path);
}
```

Когда появятся .cpp ядра: в `core/CMakeLists.txt` заменить INTERFACE на
`add_library(govno_core STATIC src/...)` + `target_include_directories(govno_core PUBLIC include)` — gui не меняется.

### 8.1 Индикаторы и остановка симуляции (договорённость gui ↔ ядро)

- **Свечение.** У индикаторов (светодиод, лампа, неоновая лампа, логический выход, сегментный индикатор, светодиодная матрица)
  есть параметр `glow` («Цвет свечения», RGB как целое `0xRRGGBB`, `ParamDef::color`) — цвет выбирает пользователь в свойствах.
  Яркость задаёт расчёт: `CircuitItem::setLight(уровни 0…1)`. Светодиод зажигается сам по току из `setElectrical` (ток / `maxCurrent`);
  у сегментного индикатора уровни по выводам `a…g, DP`, у матрицы — по ячейкам строка за строкой. Без вызова `setLight` индикатор не светится.
- **Резистор перед выводом (правило интерфейса, `gui/sim/Preflight.*`).** У светодиода, RGB-светодиода, сегментного индикатора и матрицы
  каждый подключённый вывод должен соединяться с резистором или землёй. Иначе симуляция не запускается, а на ходу — резко останавливается.
  Остальные проверки (нет земли, вырожденная матрица, не сходится…) — в ядре.
- **Общий формат причин — `SimIssue`** (`gui/sim/SimIssue.h`): серьёзность, код, текст, подсказка, `itemUid` (`CircuitItem::uid()`), выводы.
  Ядро находит проблему и вызывает `EditorWindow::stopSimulationWithIssues(issues)`; интерфейс сам: кнопка «Старт», статус «Остановлена: …»
  в панели симуляции, красные ореол/кольца у виновников, красная плашка на схеме («Показать» / «×»), записи в журнале симуляции
  (нижняя панель, двойной клик по строке — выделить элемент). Пока симуляция остановлена или идёт, схема перепроверяется при каждом изменении;
  когда проблема исправлена, подсветка и плашка снимаются сами.
- **Куда подключается ядро:** `EditorWindow::onSimulationToggled(true)` (после проверок интерфейса — передать схему и начать расчёт),
  результаты — `CircuitItem::setElectrical`, `setLight`, `setSimTime`.

### 8.2 Карта Карно как элемент и проект

- **Элемент «Карта Карно»** (`ElementType::KarnaughMap`, категория «Логика», `Dynamic::Karnaugh`): таблица `width × height` (1…16) с подписями кода Грея, диагональ с именами переменных в углу и окно «F = …» под таблицей. Размер и «Что выводить» (`output`: 0 СДНФ, 1 СКНФ, 2 минимальная ДНФ, 3 минимальная КНФ) — в свойствах. Клик ЛКМ по клетке выделенной карты меняет её 0 → 1 → X (с отменой, `ChangeCellsCommand`; первый щелчок по невыделенной карте только выделяет её, чтобы клетки не менялись случайно); работает при любом повороте/отражении (`partAt`). Параметр `pins` («Выводы»): «Убрать» делает карту только таблицей для кликов — у элемента нет ни одного вывода (`pinCount() == 0`, ручек и точек соединения нет; бит 16 варианта).
- **Контракт с ядром.** Выводы: A, B, … (сначала `bits(height)` переменных по строкам, затем `bits(width)` по столбцам) и выход F. Клетки: `CircuitItem::cells()` — 16×16 байт по строкам (`row * 16 + col`; 0, 1, 2 = X), видна верхняя левая часть `height × width`. Подписи строк и столбцов — код Грея индекса: ядру нужно перевести значение входных бит в индекс обратным кодом Грея. X — безразличное значение (ядро вправе выдать 0 или 1). `vhigh`/`threshold` — как у остальной логики.
- **Формула** считается в gui (`Karnaugh::solve`) при любой правке клеток/параметров и показывается в окне; результат хранит `CircuitItem::karnaughFormula()`.
- **Проекты.** В приложении открыто сразу несколько проектов (`ProjectHub`): «Новый проект», «Новый проект 2»… Каждая схема и карта Карно принадлежит проекту; вкладки всех проектов лежат на общих полосах (при двух и более проектах подпись вкладки «Схема 1 · Имя проекта»). Панель «Проекты» слева (рядом с разделами) показывает дерево всех открытых проектов; жирным — активный, «•» — есть несохранённые изменения, «(скрыт)» — вкладки проекта убраны с полос (данные остаются). Меню Файл: Новый / Открыть / Сохранить / Сохранить как / Переименовать / Закрыть проект (действуют на активный), ПКМ по проекту в дереве — то же и «Открыть в проводнике», «Скрыть», «Удалить проект» (удаляет и файл с диска после подтверждения). Один файл открывается один раз: повторное открытие просто переходит к проекту. Файл `.govno` — JSON: `schemes[{name, items[{type, a, b, flip, params, text, cells}]}]`, `maps[{name, width, height, cells, names}]`. Несохранённость схемы — `QUndoStack::isClean()`.
- **Несколько окон.** Любую вкладку схемы или карты можно вытащить за полосу вкладок: откроется новое окно (`EditorWindow standalone`) с этой вкладкой, страница остаётся в своём проекте (в дереве пометка «в отдельном окне»). Вкладку можно бросить на полосу другого окна; схема не принимается полосой карт и наоборот (`DetachableTabBar::kind`). Закрытие отрывного окна возвращает его вкладки в основное окно; пустое окно закрывается само.

### Компоновка выводов

- Сегментные индикаторы (3/5/7/9/14/16 сегментов) — корпус со «стеклом», выводы по двум длинным сторонам, подписи вдоль выводов снаружи. Семисегментный — как реальный 10-выводной (5161AS): сверху слева направо g, f, K, a, b; снизу e, d, K, c, DP (два общих вывода K внутри соединены). Сегменты нарисованы шестиугольниками; уровни яркости `setLight` — по сегментам a…g, DP.
- Светодиодная матрица — как реальный модуль: тёмный корпус, круглые светодиоды, выводы сверху и снизу. У 8×8 по умолчанию настоящая распиновка (16 выводов: сверху C8 C7 R2 C1 R4 C6 C4 R1, снизу R5 R7 C2 C3 R8 C5 R6 R3); параметр «Распиновка» переключает на «по порядку» (столбцы сверху, строки снизу — так же у любых других размеров).
- Сегментный индикатор: параметр «Число разрядов» 1…16. У одного разряда — свои выводы, у нескольких — общие сегментные a…g, DP и по общему выводу D1…Dn на разряд (у 4 разрядов как у реального 12-выводного: сверху D1 a f D2 D3 b, снизу e d DP c g D4). Уровни `setLight` — блоками по разрядам: ячейки цифры, затем DP.
- RGB-светодиод (общий катод) — обычный знак светодиода с тремя входами R, G, B слева (подписаны) и катодом K справа. `setLight({r, g, b})` — яркость каналов 0…1, цвет свечения и ореола смешивается из каналов (параметр `glow` у него нет).
- Цифровой индикатор — корпус с N знаками из тех же шестиугольных сегментов, показание задаёт `CircuitItem::setReadout("12.34")` (выравнивание вправо, точка склеивается со знаком); параметры «Число знаков» и «Цвет цифр» (`glow`, по умолчанию #00E676). Без показания горят тени «8».
- Дисплей инструкций (INSTR) — микросхема с тактовым входом C и шиной D0…D7, справа экран: в первой строке мнемоника команды, во второй — код (`setReadout("LDA #05\n0xA9 0x05")`); без показания «----». Параметр «Набор команд» выбирает таблицу декодирования для ядра.
- ЖК HD44780 — строки текста приходят через `setReadout` (строки через `\n`), 16 знакомест в строке; подсветка — по состоянию выводов A/K.
- Приборы (вольтметр, амперметр, омметр, пробник, контрольная точка): `setReadout` заменяет подпись показанием.
- Реальная распиновка: таймер 555 (TRIG, THR, CTRL, RESET | OUT, DIS | V+ | GND), 78xx (IN | OUT | GND снизу), LM317 (IN | OUT | ADJ снизу).
- Если на одной стороне больше 6 выводов, шаг между ними — одна клетка (16 px) вместо двух; то же у вентилей с числом входов больше 6. Подписи плотных выводов сверху и снизу чередуются по высоте.
- Подсветка: у семисегментного индикатора сегменты разнесены зазорами, у матрицы между ячейками видны промежутки. Шрифт Geist задан для приложения и для каждого класса виджетов (`Theme::applyToApplication`), номиналы и графики — JetBrains Mono.
